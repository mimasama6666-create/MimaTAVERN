## 根因与代码级修复
- **第一个错误状态**：`validateMemoryCandidate()` 将来源真实而经过自然意译的摘要转为提取式原句投影或人工审核；随后 `validateRollingCoverage()` 强制每条原始消息全文出现在摘要里才算事件覆盖。真实信息 24 天压缩成 35 字因此被拒，无法正常自动结算。
- 新增 `sourceEventLedger()`、`memoryEventKey()`、`eventFrameFlags()` 与来源有界抽象校验：仅将 **完全相同的事件模板且序号连续** 的多条来源归为一组，要求输出明确且正确的序列数量/范围；对逐组的实质文本覆盖、否定/传闻/假设/梦境，以及整段新增危险行为/新句子进行保守校验。来源为 canonical 原始消息，绝不将模型挑选的引用视作全范围证明；证据记录 message IDs、来源偏移锚点、哈希与最终 covered/missing。
- 忠实有界意译可保留自然摘要并自动提交，标记 `source_bounded` 而非伪装成 `extractive_verified`；仅 extractive 或人工确认才可作为被信任的事实源提升为核心记忆。更复杂的语义不确定性仍进入 `needs_review`，不把未知内容写成已证实事实。
- 原始来源会话在 API 返回时会重新校验 job 的 canonical 前缀哈希，允许 append-only 聊天，拒绝已编辑或删除剧情的迟到摘要，避免把过期响应错误记录成审阅候选。
- R8 的单次有限补录、分片局部人工确认、最终游标事务、可信事实转核心、历史不丢、超时/429 不假成功全部保留。修复旧第五轮与 R8 两份复现脚本默认相对路径，无生产改动。
- **能力边界**：事件单元采用确定性文本/数值/风险词校验，不能证明任意复杂中文语义、代词指代、因果或反讽绝对正确；未有真实模型语义黄金集时不可宣布根因在全部剧情上闭环。
