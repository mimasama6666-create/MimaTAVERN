# 咪嘛馆 R14.2 · 坏回复手动恢复

本包包含 R14 完整程序、R14.1 正则编辑保存修正，以及本次手动恢复功能。仅修改咪嘛馆，不改 MIMAMAO/QQBOT。

## 使用

将本包根目录的程序文件覆盖到现有咪嘛馆目录，保留原有网站地址，重新载入页面。已更新相关资源的缓存版本号；不需要清空浏览器数据。

在「设置 → 诊断日志」中查看异常记录。每条坏回复，以及选中后的详情，均有「手动恢复」按钮。先核对“未采纳的模型文本”，再确认恢复。

恢复直接使用日志中保留的文本，不调用模型、不自动重试、不生成后台摘要、不重复运行输出正则。显示正则和安全 HTML 渲染照常生效。原服务端错误与 finish_reason 继续保留，不会伪装成原请求成功。

- 原生发送/自动推进：补回原轮角色回复。
- 原生重说：替换已锁定的原目标，替换前保存旧版本。
- 原生续写：追加到原回复，追加前保存旧版本。
- 酒馆兼容发送/续写：使用原回合的结算事务；继续验证 MVU 状态，续写保留 sidecar 旧正文。
- 重复点击有幂等保护。人工确认仅绑定对应正文，不会全局关闭坏回复拦截；后续上下文保留该正文。

## 不能恢复的情况

空回复没有可恢复文本。诊断被清理、诊断副本被裁剪、失败任务已重试/替换，或原正文/版本发生变化时，系统会说明原因，保持当前剧情不变。旧兼容日志如果无法可靠对应具体尝试，也不猜测写入。服务端本来就没返回的后半段无法补造。

手动确认不证明模型文本完整；上游结束标记仍可能表示内容拦截或截断。若启用了 HTML 完整性检查，恢复仍需满足它。

## 本轮检查范围

遵照要求，仅做 JavaScript 语法、差异格式和静态调用链检查。未运行测试套件、浏览器交互测试、模拟模型测试或真实模型调用。不能据此宣称实机验证通过。旧包中的历史测试文件仍保留，但本轮没有执行。

## 回退

包内 `_R14_2_rollback/` 保存本次修改前的程序文件（R14.1 基线）。需要回退时，将其中的文件覆盖回同级程序目录。不要删除浏览器数据；本次没有数据库版本升级或破坏性迁移。已恢复的正文不会因回退自动删除，原生旧版本仍可查看。
