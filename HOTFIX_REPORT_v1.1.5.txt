MIMAMAO Tavern · v1.1.5
Artifact Protocol V2 / Zero-Escape Regex Import / Paid Repair Transparency Hotfix

============================================================
0. SOURCE OF TRUTH / CONSTRUCTION SCOPE
============================================================

唯一施工基线：MimaTAVERN-main-v1.1.4-FULL.zip

本轮是 v1.1.4 的增量 Hotfix / DLC，不重做现有器官，不顺手重构。

真实问题：
- v1.1.4 的“修复此工件”会真实调用助手模型，因此请求成功后会产生 API 费用。
- 但修复模型仍需重新输出一个几千 token 的巨大严格 JSON；Regex pattern、replacement、HTML、CSS 里的引号/反斜杠任一处少一次 JSON escape，整包仍会在本地 JSON.parse 阶段失败。
- 因此会出现：API SUCCESS / 已计费，但 ARTIFACT VALIDATION FAILURE / 未写入。

本轮目标：从运输协议层消灭“大型 Regex Bundle 必须手写巨大 JSON escape”的脆弱点，同时保留旧 V1 工件兼容与 fail-closed 数据安全。

============================================================
1. ARTIFACT PROTOCOL V2 · ZERO-ESCAPE
============================================================

新增：<MIMA_ARTIFACT_V2 kind="..."> 分段工件协议。

Regex Bundle 不再把以下内容塞进一个巨大 JSON 字符串：
- Preset content
- RegExp pattern
- Replacement HTML
- CSS

大型文本改为 CDATA 分段传输，例如：

<PATTERN><![CDATA[
<ST>([^¦]*)¦([\s\S]*?)</ST>
]]></PATTERN>

<REPLACEMENT><![CDATA[
<div class="mima-panel">$1</div>
]]></REPLACEMENT>

因此：
- HTML 双引号无需写成 \"
- Regex \s / [\s\S] 无需再做 JSON 二次转义
- $1 / $2 原样保存
- CSS 原样保存

咪嘛馆本地代码负责把 V2 各段重新组装为 canonical artifact object，再进入现有 Regex/Preset/CSS 保存链。

============================================================
2. LEGACY V1 继续完整兼容
============================================================

旧的：
<MIMA_ARTIFACT>{...JSON...}</MIMA_ARTIFACT>

仍然继续支持：
- strict JSON
- v1.1.3 safe repair
- v1.1.4 loose self-healing

没有删除旧解析器，没有强制迁移历史聊天，没有破坏旧已经生成的工件。

新生成的 Regex / Preset / CSS 工件默认要求助手使用 V2。

============================================================
3. AI RESCUE REPAIR · PAID CALL TRANSPARENCY
============================================================

原“修复此工件”升级为：
“AI 救援修复（会计费）”

点击前明确确认：
- 会真实调用当前助手模型
- 可能产生 API 费用
- 每次点击只调用一次
- 绝不自动付费重试第二次

AI Repair 不再要求模型重写严格 JSON。
现在要求：
Broken Legacy V1 / Broken V2
→ 逐字段搬运
→ MIMA_ARTIFACT_V2 Zero-Escape
→ 本地 V2 parser
→ schema / Regex 后续现有校验
→ 通过才允许替换原工件

Repair temperature 会压到 0.1~0.2 之间，提高运输稳定性；仍使用助手自己选择的模型，正文模型配置不受影响。

============================================================
4. PAID RESPONSE NEVER DISAPPEARS AGAIN
============================================================

新增 repairAttempts 本地归档：
- time
- model
- raw model response
- success
- error

最多保留最近 5 次。

如果 AI 请求已经成功并产生计费，但 V2 本地验收仍失败：
- 原工件不覆盖
- 不自动再次调用模型
- AI 返回全文保留
- 错误原因保留
- UI 可展开“查看最近 AI 修复结果”
- Toast 明确提示“AI 已返回内容并完成计费，但本地验收未通过”

因此不会再出现：
花了钱 → 修复失败 → 模型到底输出了什么也看不到。

============================================================
5. DATA SAFETY / FAIL CLOSED
============================================================

保持：
- 解析失败 != 空工件
- 解析失败不得保存半残 Regex
- 解析失败不得覆盖原历史
- AI rescue 失败不得覆盖原工件
- 成功替换前先把原内容写入 versions
- 成功后的 artifactProtocol 标记为 v2
- 不使用 eval()
- 不使用 Function(modelOutput)

saveArtifact 仍复用原有：
MimaRegexEngine.validatePack
→ /regex-packs
→ /presets
→ /css-presets
→ Current Session additive mount

没有绕过旧验证器。

============================================================
6. UX DETAILS
============================================================

- 失败卡明确显示“本地安全解析/自愈（免费）已经尝试”。
- AI 救援按钮明确标注“会计费”。
- 成功 V2 工件显示“V2 Zero-Escape”标签。
- 旧 JSON 工件显示“Legacy V1”标签。
- 聊天流式过程中，一旦助手开始输出 MIMA_ARTIFACT / V2 工件运输块，正文聊天会停止展示运输层原文，避免几千行 Regex/HTML 在聊天区疯狂刷屏；最终工件卡照常出现。
