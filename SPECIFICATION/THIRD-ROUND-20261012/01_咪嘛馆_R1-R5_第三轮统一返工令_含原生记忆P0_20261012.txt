【当前已证实的首发错误状态】
M0-1｜P0：app.js triggerChat() 在调用任何模型之前对同 session memoryTask 直接 return/Toast，导致记忆运行期间无法跑剧情。这是程序主动阻塞，不是 API 故障。generateCoreMemory()/generateFactMemories() 也将 memoryGenerating 与 isGenerating 相互排斥。必须消除两边互斥，UI、生成按钮、输入框、剧情发送不得被记忆总结阻断。Speech Turn 优先；记忆是独立的异步后台任务，关闭设置弹窗或切 Tab 无碍。已有独立 activeRequest / memoryTask 只是取消控制器分离，不等于任务真正不阻塞。
M0-2｜P0：standalone-core.js 的事实记忆每范围依次调用 summarizeFactText -> callModel，超长范围再分块+合并；核心记忆又会分片+终稿。单次空回复、400、429 或断线将令整次失败，进度可能长时间无实质变化。必须记录每次真实请求的阶段、requestId/jobId/attempt、provider/model、实际参数结构、HTTP status、响应类型、finish_reason、输出可见字符数、tokens/usage（如上游提供）、响应形状、错误来源；日志不得泄露 API Key、完整私人剧情或原始隐藏推理。先证明第一个异常输出状态在哪里出现，再决定是否修改 payload、兼容解析、输出上限或模型配置。禁止一遇空文本就静默换模型、填假摘要、增加盲目 retry、延时或减少上下文。
M0-3｜P0：standalone-core.js processStoryTurn() 先 await refreshSummary() 再请求正文；自动 Rolling Summary 失败被 catch 后 console.warn 并照常跳过，没有持久的 degraded 诊断。这仍是辅助总结进入主 Reply 串行关键路径。重构为正文正常发送后/独立任务队列的非阻塞处理（也要考虑原有摘要覆盖范围不能被跳过），失效时明确保留未处理区间和可重试状态，不得让总结出错吞没剧情或污染历史。
M0-4｜P0：后台任务的唯一结算权威、稳定 jobId/attemptId、来源消息 ID/修订/内容 hash+覆盖区间、阶段 checkpoint、完成/失败/取消状态，必须可持久识别；同一任务不重复记账或结算。允许玩家在总结期间继续说话，后台只提交针对开始时经过验证的来源前缀/记忆字段，不能把旧快照覆盖新增聊天、编辑或手工记忆。仅靠 append-safe 内存比较和全局 storeRevision 不足以承诺跨 Tab、刷新、并发安全；对主库 CAS、刷新、断电、保存阶段做具体源码与浏览器验证；读失败不得视为空库。已有旧记忆应保持直至新版本真正 commit。由于浏览器页面刷新无法继续原有 JS Promise，要有可恢复任务记录与安全的继续/重试入口，不能把“后台”误报为浏览器已关闭仍连续执行。
M1-1｜P1：记忆真实性与作用审计：本版确实将 manualMemory.core 和 facts 注入 system prompt，离线验证过，不能称完全摆设；但仅取最近 N 段 facts + 整段 core，不能等同检索增强长期记忆，也没有结果正确率证明。加本轮 Prompt Inspector“实际命中的记忆 ID/来源/覆盖轮次/版本/注入字符/预算/被排除原因”，区分 Rolling Summary/核心/事实/Pinned/当前原文。将同一事实的重复和相互矛盾信息明确标注；历史编辑、分支切换、重说、删除必须使对应摘要进入 stale/unverified，不能继续以高优先级既定事实注入。禁止用静默裁短 History/Persona 来节约 tokens。保持手动开关和所有旧字段兼容；未被证明支持的复杂检索只能标为未实现。
M1-2｜P1：可用性与性能：总结改为增量、按可溯源轮次窗口和合理模型输入预算规划，避免每次核心记忆都重跑全部原文；相同输入无需做无意义的多次模型调用，但必须保留实际需要的合并和语义。阶段性候选产物可安全 checkpoint，失败不发布半成品，也不强迫用户重新付费跑完已验证的完整阶段。测请求次数、输入输出 tokens、耗时 p50/p95、摘要覆盖率和剧情延迟，保留完整旧剧情和未压缩原文，不以减少上下文换稳定。并发 API 额度应以玩家剧情优先：可暂停记忆尚未启动的下一块，不取消/占用主回合，不因 memory 429 导致 chat 必然失败；限制任务总并发与总请求量但不能无限占用或死循环。前端进度分“准备/请求/已返回/校验/保存/已完成或失败”真实阶段，长请求展示经过时间，不伪造百分比或承诺时间。
M1-3｜P1：模型输出保护：HTTP 200 content:''、content:null+reasoning_content、finish_reason:length、完整正文被解析器漏读、SSE DONE/EOF、400 不支持 temperature、429、5xx、空响应/网关 HTML、请求已完成但保存 CAS 失败，必须区分“模型没有产生可用正文”“解析契约不匹配”“网络/限额”“保存结算失败”，每种保留原始记忆且给能诊断的错误。禁止把 reasoning_content、refusal、工具结果误当成记忆事实，JSON/纯文本应通过独立 schema/safety 检查。可增加不调用真实 API 的模拟和真实接口选择性对照。真实 API 未测不得归因上游。
M1-4｜P1：记忆可信性回放：不少于 3 个独立长剧情测试集（角色关系/关键物品位置/已关闭与未解决任务），跨 50/200/500 轮，先有明确真值表，再生成记忆→保存→关设置→继续发送→检查模型实际 prompt 与用户可见回答；有/无记忆的对照测试，统计正确召回、误记、过时、矛盾、泄漏和重复。可控 deterministic mock 用于契约和 UI，真实 LLM 用于行为质量（不能因 mock 通过宣称真正记住）。兼顾小说章节记忆，与聊天记忆隔离；旧档案及导入/导出保真。
