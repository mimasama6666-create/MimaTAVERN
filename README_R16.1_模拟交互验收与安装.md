## 本次修复

1. **启用作者脚本后发送误报忙碌。** 正式发送已经持有作者快照锁，内部又调用公开预览入口，重复进入同一把锁而被拒绝。内部预检改用已受外层保护的实现；公开预览与其他并发操作仍保留原有保护。
2. **快捷回复管道宏被误拦截。** `{{pipe}}` 与已支持的 `{{getvar::名称}}` 交给具体 STscript 步骤展开。普通台词/仅填入按钮继续拒绝未支持宏，未知命令不会变成玩家台词发送。
3. **多个作者脚本的共享变量快照过期。** 初始化及写入完成后，把已提交快照同步给同故事中空闲且已授权的其他作者。未结算动作、冻结状态与脏快照不会被强制覆盖；数据库原有修订冲突校验保留，并验证旧快照写入仍被拒绝。
4. **进入故事时旧草稿覆盖新输入。** 恢复目标故事的草稿移至异步载入之前；延迟载入完成时不再重写输入框。通过故意延迟预览、期间输入新文字的稳定复现验证。

以上问题均先复现失败，再修正并通过受影响链路。测试脚本初版中折叠区定位及未关闭工具弹窗的问题已修正，未把这些测试脚本问题计入产品修复数量。

## 已实际核对的重点

- 独立脚本与 Quick Reply JSON 通过文件入口导入，默认不启动、不自动执行 startup 钩子。
- Vue / lodash / Zod 原生 ES module 及经典 jQuery / lodash / Vue / Zod 真库在离线隔离页面运行。
- Zod 管理器保留无效草稿、不写坏值，能转换合法字段并保留额外字段。
- chat/message/script 变量保存、跨作者广播、消息事件、停止与重载保留；未授权读取明确报错。
- 快捷回复填入、撤销草稿、STscript 管道、本地变量、正式发送、未知命令/宏拦截。
- 正常 JSON 发送、SSE 续写、重复发送防重、等待回复期间的新草稿保留。
- content_filter 有正文时保留候选；在坏回复列表点击手动恢复，原任务一次落库且不请求模型。
- 续写中断后原回复保持不变；手动恢复只追加一次，旧版本和原错误标记保留。
- HTTP 503 不自动重试、不插入空角色消息；没有正文时点击恢复会说明无法恢复。
- 长文降级保留原文，短屏工具弹窗的关闭按钮可达，默认 HTML 没有额外空白行。
